## 0. 무엇을 부탁하는가

세 가지다.

1. **타입 스케일 정리** — 지금 세리프 17종·산세리프 12종·라운딩 10종이 쓰인다(§5, §6). 이건 디자인이 아니라 축적된 즉흥이다.
2. **그래픽 언어** — 일러스트·모션이 한 벌도 없다. 이 앱이 팔아야 하는 개념(여덟 걸음 / 공명 / 시차 동행)이 전부 추상이라 지금은 원과 선으로 때우고 있다(§7).
3. **아직 없는 화면** — 러닝 중 화면(와이어프레임 08~11)이 개편 전 상태 그대로다. 야외·야간 조도 문제까지 걸려 있다(§8).

돌려주는 형식은 §9를 따라 주면 코드에 바로 착지한다.

## 1. 제품 한 장

**멀리 있어도, 발이 맞는 순간을 만든다** — 사운드 리듬 기반 커뮤니케이션형 러닝 앱(iOS).
핵심 철학: **"기록이 아니라 관계."** Strava식 퍼포먼스 경쟁이 아니라, 떨어져 있는 두 사람이 발을 맞추는 감각을 판다. 동시에 달리는 것은 정점이지 전제조건이 아니다 — 혼자 달려도 관계에 쌓이고, 겹치면 터진다.

- **케이던스가 심장**: 곡의 BPM이 내 발걸음을 실시간으로 따라온다. 들리는 발소리는 상대의 것만.
- **공명(resonance)**: 두 사람의 케이던스가 맞아떨어지는 순간. 제품의 가장 희소한 보상.
- **8분 에피소드**: 시간 기반 세션(거리 아님). 완결 내장. 끝나면 잔향 30초 — 계속 뛰면 자유런으로 이어짐.
- **고스트런 = 시차 동행**: 상대의 과거 러닝 리듬과 함께 달린다. 추월 게임이 아니다.
- **러닝 중 화면 조작 제로**: 시작 후 종료까지 화면을 보거나 만질 필요가 0이어야 한다. 세션 화면은 조작판이 아니라 방송판.

1차 타깃은 **기록이 부끄러운 사람들**이다. 공개가 기본이면 그들은 첫 러닝을 남기지 않는다. 화려함보다 안전함이 먼저다.

## 3. 절대 규칙 (바꾸면 제품이 바뀐다)

### 색의 의미
**나 = lime, 상대 = coral, 공명 = 골드.** 섞지 않는다. kcal·거리 같은 일반 지표는 ink/mid.
골드가 "우리 둘이 만든 것"이라는 희소성을 가지려면 **공명 외에는 절대 쓰지 않는다.** 이건 색 선택이 아니라 문법이다.

| 토큰 | HEX | 용도 |
|---|---|---|
| `paper` | `#F0EAE0` | 기본 배경 |
| `canvas` | `#EBE4D6` | 카드/서브 배경 |
| `lime` | `#C5E040` | **나** |
| `limeDark` | `#6A9810` | 나(텍스트/진한 변형) |
| `coral` | `#F05840` | **상대** |
| `coralDark` | `#B03020` | 상대(진한 변형) |
| `ink` | `#1A1A16` | 본문/제목 |
| `resonance` | `#D4A84B` | **공명 전용 골드** |
| `amber` | `#D97706` | 경고/강조 보조 |
| `mid` | `#78746E` | 보조 텍스트 |
| `dim` | `#B0ACA6` | 약한 텍스트/섹션 라벨 |
| `line` | `rgba(26,26,22,.09)` | 구분선·카드 테두리 |

무드: 따뜻한 종이 질감, 아날로그. 네온·다크테크·게임 UI 아님.

### 금지
1. **이모지 금지** — §4 참조. 두 번 시도해 두 번 실패했다.
2. **승패·순위·앞서기/뒤처지기 언어 금지** — UI 카피 포함. 쓰는 말은 **가까워짐 / 나란함 / 멀어짐** 셋뿐. 리더보드·랭킹 UI 금지.
3. **러닝 중 화면 조작을 요구하는 UI 금지** — 세션 화면의 조작 요소는 일시정지 하나만.
4. **수익화 UI 금지** — 결제·구독 화면·버튼 일절.
5. **죄책감 카피 금지** — "스트릭 잃어요!" 류. 알림·CTA는 기대감 문법만.
6. **눌러도 아무 일 없는 버튼 금지** — 준비 안 된 기능은 자리를 비워 둔다. 결과 화면의 트랙 재생 버튼이 지금 없는 이유다(§8-2).

## 4. 폰트 — 깨뜨려 봐야 아는 것들

**이 환경에는 시스템 폰트 폴백이 아예 작동하지 않는다.** 2026-08-16에 세 조건을 나란히 렌더해 확인했다. `fontFamily`를 지정하지 않으면 이모지는 물론 **한글까지 두부(?)로 깨진다.** 한글이 나오는 건 폴백 덕분이 아니라 NotoSansKR을 번들해 이름으로 직접 지정했기 때문이다. 여기서 따라오는 것들:

- **쓸 수 있는 폰트는 번들된 둘뿐이다** — `InstrumentSerif`(타이틀·숫자, italic), `NotoSansKR`(본문).
- **Instrument Serif에는 한글 글리프가 없다.** 세리프 타이틀의 한글은 NotoSansKR로 폴백된다. 그래서 세리프 타이틀은 실제로는 **두 폰트가 섞여 렌더된다** — 라틴/숫자는 세리프 이탤릭, 한글은 산세리프. 이 혼합이 지금 브랜드 타이포의 실체다. 개선안이 이걸 전제로 해야 한다.
- **세리프와 숫자 사이 공백이 좁게 렌더된다.** `'오늘의 8분 시작'`이 화면에서 `'오늘의8분 시작'`처럼 붙어 보인다(공백을 Instrument Serif가 그리기 때문). 실제로 관찰된 문제이고, 타입 개선에서 다뤄 주면 좋겠다.
- **이모지는 쓸 수 없다.** `fontFamilyFallback`에 `Apple Color Emoji`를 넣는 방법은 두 번 실패했다. 남은 길은 이모지 폰트를 번들하는 것뿐인데 IPA가 30%가량 커진다 — 지금은 비용이 이득보다 크다는 판단. **Material Icons / 커스텀 벡터 / 기하 기호(▲ ● ★)만** 쓴다(기하 기호는 NotoSansKR에 들어 있어 정상 렌더).
- **번들 폰트에 없는 글리프는 안전망이 없다.** 다른 언어·특수 기호를 새로 도입하면 조용히 두부가 된다.
- 예외: **Flutter가 그리지 않는 문자열**(공유 시트 텍스트, 푸시 알림 본문)은 받는 쪽이 시스템 폰트로 렌더하므로 이모지를 써도 된다.

새 폰트를 제안한다면 ① 한글 글리프 유무 ② IPA 용량 증가분을 함께 적어 주면 판단할 수 있다.

## 5. 타입 스케일 — 지금 상태

지금 코드에서 실제로 쓰이는 크기다. 정리 대상이라는 뜻으로 그대로 적는다.

**세리프(`GoTheme.serif(n)`, 전부 italic)** — 17종
`68 · 44 · 40 · 30 · 28 · 26 · 24 · 23 · 22 · 21 · 20 · 19 · 18 · 17 · 16 · 15 · 12`
가장 많이 쓰인 것: **24**(화면 타이틀) · **20** · **18**(알약 버튼) · **22**

**산세리프(`fontSize`)** — 12종
`40 · 26 · 18 · 17 · 16 · 15 · 14 · 13 · 12 · 11 · 10 · 9`
가장 많이 쓰인 것: **13**(본문) · **11**(캡션·섹션 라벨) · **12** · **14**

**섹션 라벨**만 규칙이 있다: 11px / weight 600 / letter-spacing 1.2 / `dim`.

→ **과제**: 세리프 4~5단계, 산세리프 4~5단계로 줄인 스케일과 각 단계의 용도. 줄이면서 지금 화면들이 어떻게 바뀌는지도 함께 보여 주면 좋겠다.

## 6. 그리드 — 지금 상태

**개편 화면(온보딩·홈·오늘의 상대·쿨다운·결과)은 한 격자를 지킨다:**

| 항목 | 값 |
|---|---|
| 화면 여백 | `24 / 28(위) / 24 / 20(아래)` |
| 요소 간 간격 | `14` |
| 카드 | 흰 배경 + `line` 1px 테두리 + 라운딩 `20` |
| 카드 높이 | `160`(히어로) · `130` · `110` · `84` · `72` · `52`(접힘 헤더) |
| 주 버튼 | 높이 `52` / 라운딩 `26`(알약) / `ink` 배경 / `paper` 세리프 18 |
| 보조 버튼 | 높이 `46` / 라운딩 `16` / 흰 배경 / `line` 테두리 |
| 원형 요소 | 여덟 걸음 링 `210`(stroke 6, 8조각) · 녹음 원 `160` · 아바타 `46` |

**개편 이전 화면(페이스메이트·설정·프로필·로그인·러닝)은 다른 격자를 쓴다:** 좌우 여백이 `22`·`24`·`28`로 섞여 있고 라운딩이 `12·14·16·18·22·24`로 흩어져 있다. 라운딩은 전체 10종.

→ **과제**: 라운딩 3~4종으로 수렴, 여백 한 값으로 통일, 카드 높이의 리듬(지금 값들이 임의적인지 아닌지 판단). 개편 이전 화면을 새 격자로 끌어올 때의 순서도 함께.

## 7. 그래픽 — 지금 없는 것

이 앱이 팔아야 하는 개념이 전부 추상인데, 그걸 그릴 언어가 없다. 지금은 이렇게 때우고 있다:

- **여덟 걸음** → 8조각으로 끊긴 링, 한 걸음에 한 칸 점등 (`01-eight-steps.png`)
- **공명** → lime 원과 coral 원이 겹치고 교집합만 골드 (`02-demo-run.png`)
- **오늘의 리듬** → 케이던스 꺾은선 (`13-result.png`)
- **브랜드 마크** → 숨쉬는 두 원 (스플래시·결과 카드)

→ **과제**: 이 넷을 하나의 언어로 묶는 것. 특히
- **공명의 순간** — 지금은 정적인 벤 다이어그램. 실제로는 8초 지속돼야 일어나는 사건이라 **시간이 들어간 표현**(모션)이 필요하다.
- **시차 동행** — 같은 시각이 아니라는 것을 그림으로 말하기. 지금은 표현 자체가 없다.
- **앱 밖 그래픽** — 앱 아이콘, 공유 카드(인스타 스토리 규격 — 성장 엔진의 핵심), 스토어 스크린샷. 하나도 없다.

## 8. 열려 있는 과제 (우선순위 순)

### 8-1. 러닝 중 화면 (와이어프레임 08~11) — 가장 큼
개편 전 화면이 그대로 돌고 있다. 제약이 특이하다:

- **읽는 화면이 아니라 곁눈질하는 화면**이다. 달리는 사람은 3초 이상 못 본다. 현재 규칙: 값은 34px 이상, 꼬리표만 작게.
- 조작 요소는 **일시정지 하나**. 나머지 입력은 귀·발·이어폰 꼭지.
- 상태는 넷: 솔로 / 고스트 합류 / 공명 / 잔향 30초.
- **공명의 골드가 유일한 '사건' 표현**이다.
- **조도 문제**: `paper`(#F0EAE0) 크림 배경이 한낮 직사광과 야간에 어떤지 검증된 바 없다. 다크 변형을 둘지가 열린 결정 — 두면 색 의미 규칙을 다크에서 다시 정의해야 한다.

### 8-2. 결과 화면의 '오늘 만든 트랙'
§5-3의 주인공은 "내 리듬으로 렌더링된 1분 음원"인데 음원 스템이 아직 없어서, 지금은 케이던스 파형이 그 자리를 대신하고 재생 버튼은 두지 않았다. 스템이 준비되면 붙는다 — **재생 UI를 미리 설계해 두면** 그때 바로 얹을 수 있다.

### 8-3. 개편 이전 화면 끌어올리기
페이스메이트·설정·프로필·로그인이 옛 격자에 남아 있다. 새 격자로 옮기는 순서와, 옮기면서 정리할 것.

### 8-4. 빈 상태(empty state)
후보가 없을 때·친구가 없을 때·기록이 없을 때가 이 제품에서는 **흔한 상태**다(Day 0 유저가 1차 타깃이므로). 지금은 텍스트로만 처리돼 있다. `07-today-partner.png`가 그 예.

## 9. 돌려줄 때 — 코드에 착지하려면

- **색은 토큰 이름으로.** `#C5E040`이 아니라 `lime`. 새 색이 필요하면 이름·용도·기존 토큰과의 관계를 함께.
- **간격은 정수로**, 되도록 2 또는 4의 배수.
- **아이콘은 Material Icons 이름**(예: `Icons.expand_more`) 또는 SVG path. 래스터 이미지·이모지는 안 된다.
- **모션은 시간과 커브로.** "부드럽게"가 아니라 "160ms / easeOut". 지금 쓰는 값: 눌림 0ms→90ms, 화면 전환 150ms, 접힘 160ms.
- **폰트는 번들된 둘 안에서.** 벗어나면 §4의 조건을 함께.
- **다크 변형을 제안하면** 색 의미 규칙(나/상대/공명)이 다크에서 어떻게 유지되는지까지.
- 화면 크기 기준은 **390×844**(와이어프레임과 같음). 실제 확인은 iPhone 16e 시뮬레이터(1170×2532 @3x)에서 한다.
