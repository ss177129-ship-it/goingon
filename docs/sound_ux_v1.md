# 고잉온 — 사운드 UX 설계서 v1

전제: 세션 UI 개선 프롬프트 1~4 완료 (공명 이벤트 레이어 존재).
제약: **케이던스 코드가 없거나 부실함** → 이 설계는 케이던스 없이 출발한다 (아래 참고).

---

## 0. 케이던스가 없다는 것에 대하여

**케이던스 부재가 사운드를 막지 않는다.** 지금 앱의 closeness는 페이스 기반으로
이미 동작하고, 사운드 시스템의 90%는 closeness와 이벤트만 소비한다.

그래서 두 트랙으로 분리한다:

| | 내용 | 의존성 |
|---|---|---|
| **트랙 A (이 문서)** | 공명 사운드 + 신호음 + 브리핑 | closeness · 이벤트 레이어만 |
| **트랙 B (부록)** | 케이던스 수집 → 리듬 레이어 승격 | CMPedometer 브리지 |

트랙 A를 먼저 완성해서 내보내고, B는 데이터가 쌓인 뒤 얹는다.
**케이던스 리듬은 사운드 시스템의 확장이지 전제가 아니다.**

---

## 1. 설계 원칙 (다섯 줄)

1. **소리는 상태 언어의 번역이다.** "나란히"가 화면에 보이면 귀에도 들려야 한다.
   새로운 정보를 소리로 만들지 않는다.
2. **실패음은 없다.** 멀어지면 소리가 조용해질 뿐, 경고하지 않는다.
3. **유저의 음악이 왕이다.** 우리는 그 위에 얹는 손님이다 (.mixWithOthers).
   손님이 시끄러우면 쫓겨난다.
4. **화면과 같은 시정수.** 모든 연속 변화는 kSharedSmoothingTimeConstant(1초)를 쓴다.
5. **침묵이 기본값.** 아무 일도 없으면 아무 소리도 없다. 소리가 나는 순간이
   희소해야 의미가 생긴다.

---

## 2. 사운드 맵 — 무엇이 언제 울리는가

이벤트 레이어의 스트림을 그대로 구독한다. 새 트리거를 만들지 않는다.

### 연속 레이어 (1개뿐)

| 소스 | 소리 | 동작 |
|---|---|---|
| smoothedCloseness | **공명 패드** (저역 위주 지속음) | closeness 0.70 미만 = 무음. 0.70→1.00에서 볼륨 0→100%로 페이드. 시정수 1초 |

- 패드는 **aligned 상태부터만** 존재한다. 세션 내내 깔리는 배경음악이 아니다.
  가까워졌을 때만 공간이 열리는 느낌 — 희소성이 보상을 만든다.
- 음악과 조성 충돌을 피하기 위해 특정 코드성 화음 대신
  **저역 드론 + 배음** 구성 (프로토타입 pad_loop.wav 계열).

### 이벤트 사운드

| 이벤트 | 소리 | 햅틱 (기존 UI와 동일 순간) |
|---|---|---|
| resonanceEntered | **chime_match** 1회. 이 앱에서 가장 좋은 소리여야 한다 | mediumImpact |
| resonanceHeld(30s/60s) | 패드에 배음 레이어 1장 추가 (소리 자체 추가 아님) | 없음 |
| stateChanged(→drifting) | **소리 없음.** 패드가 1초에 걸쳐 잦아드는 것이 전부 | 없음 |
| signalSent | 짧은 상승음 (0.2초, 작게) — "나갔다" 확인 | lightImpact |
| signalReceived(tap) | 낮은 우드블록류 1타 — "여기 있어" | lightImpact |
| signalReceived(swipe) | 밝은 2연타 — "힘내" | mediumImpact ×2 |
| signalReceived(longPress) | 부드러운 하강음 (1초) — "천천히 가자" | heavyImpact |
| milestone(1km) | **음성 브리핑** (아래 §3) | 없음 |

규칙:
- 수신음 3종은 **눈 감고 구분 가능**해야 한다 (음높이·타수·길이가 모두 다름).
- 신호 수신음은 송신음보다 커야 한다. 내 확인음은 작게, 상대의 존재는 크게.
- resonanceEntered chime은 세션당 아무리 많아도 좋다 — 이게 보상의 핵심 화폐다.
  단 재진입 쿨다운은 이벤트 레이어의 히스테리시스가 이미 보장한다.

### 금지 목록

- 멀어질 때 나는 모든 소리 (경고음, 하강 알림 등)
- 세션 시작/일시정지 등 화면으로 이미 아는 것의 중복 알림음
- 30분 내내 존재하는 소리 (패드조차 aligned 이상에서만)

## 3. 1km 음성 브리핑

### 문장 구조 — 3요소 고정, 이 순서

```
"3킬로미터. 5분 32초. 지수는 3.4킬로."
```

1. 내 누적 거리 (짧게)
2. 이번 킬로미터 스플릿
3. **상대 정보 한 조각** — 이 앱만 할 수 있는 문장. 절대 빼지 않는다

상대 정보의 우선순위 (해당되는 첫 번째 것 하나만):
1. 상대가 방금 신호를 보냈다면: "지수가 힘내래요"
2. 공명 유지 중이라면: "지금 나란히예요"
3. 기본: "지수는 3.4킬로"

### 구현 규칙

- flutter_tts. 한국어 보이스로 숫자 읽기를 **먼저 실기기에서 검증**
  ("5분 32초", "3.4킬로"가 자연스럽게 읽히는지. 페이스 표기는 특히 잘 틀린다)
- 발화 중 음악은 **duck** (볼륨만 낮춤, 정지 금지). 발화 끝나면 1초에 걸쳐 복귀
- 브리핑 중 이벤트 사운드는 큐에 넣지 말고 **버린다** (뒤늦게 울리는 chime은 혼란)
- 전체 발화 길이 4초 이내. 넘으면 요소를 줄인다
- 설정에서 끌 수 있어야 한다 (브리핑만 / 전체 사운드 각각)

## 4. 오디오 세션 구성 (모든 것의 전제)

```
카테고리: playback
옵션: mixWithOthers  (평상시 — 유저 음악과 공존)
      duckOthers    (브리핑 발화 순간에만 활성화 후 해제)
Info.plist: UIBackgroundModes에 audio 추가 (location과 공존 확인)
```

- audio_session 패키지로 설정. **앱 시작이 아니라 세션 시작 시** 활성화하고
  세션 종료 시 비활성화한다 (러닝 안 할 때 오디오 세션을 잡고 있으면 안 된다)
- 전화 수신 인터럽션: 세션 오디오는 죽어도 되지만 **복귀 시 자동 재개**되어야 한다
- 이어폰 뽑힘: 스피커로 이어가지 말고 사운드 레이어만 조용히 정지
  (주머니 속 스피커 소리는 사고다). 러닝 기록은 계속된다

## 5. 재생 엔진과 에셋

- **flutter_soloud** (저지연 루프·페이드 지원). audioplayers는 지연이 커서 이벤트음에 부적합
- 에셋 (기존 프로토타입에서 확정, 최종 음원은 추후 교체):

```
assets/audio/
  pad_resonance.wav      공명 패드 루프 (심리스, ~8초)
  chime_match.wav        공명 진입
  sig_send.wav           송신 확인
  sig_tap.wav            수신 · 여기 있어
  sig_cheer.wav          수신 · 힘내 (2연타)
  sig_easy.wav           수신 · 천천히 (하강)
```

- 전부 모노 또는 좁은 스테레오, -14 LUFS 근처로 통일. 음악 위에 얹혔을 때
  튀지 않는 것이 목표
- 프로토타입 검증용으로는 기존 goingon_sound_proto의 합성 에셋을 그대로 사용

## 6. 검증 시나리오 (데모 모드로 전부 가능)

1. 음악(스포티파이) 재생 → 세션 시작 → **음악이 끊기지 않는다**
2. 데모 진행 → aligned 진입 → 패드가 1초에 걸쳐 올라온다
3. resonant 진입 → chime + 햅틱 + (UI의 골드 링)이 **같은 순간**이다
4. 경계 근처에서 패드 볼륨이 떨리지 않는다 (히스테리시스+스무딩 검증)
5. 지수의 신호 3종 → 눈 감고 구분된다
6. 1km 도달 → 음악이 살짝 가라앉고 브리핑, 끝나면 복귀
7. 화면 끄고 주머니에 → 전부 계속 동작한다
8. 전화 수신 → 종료 후 사운드 자동 복귀
9. 이어폰 뽑기 → 스피커로 새어나오지 않는다

# 부록: 트랙 B — 케이던스 (다음 스프린트)

사운드 v1이 나간 뒤에 진행. 순서:

1. **수집만 먼저** — 플랫폼 채널로 CMPedometer.currentCadence 브리지 (iOS 9+라
   현재 타깃에서 사용 가능). 세션 데이터에 조용히 기록만 한다. UI 변화 없음
2. **데이터 확인** — 몇 세션 모아서 케이던스 신호 품질 확인 (주머니/암밴드 편차)
3. **리듬 레이어 승격** — 품질이 확인되면:
   - closeness 계산에 케이던스 근접도를 혼합
   - 패드 위에 상대 케이던스 템포의 리듬 루프 추가 (기존 BPM별 루프 에셋 사용)
   - 이때도 이벤트 레이어 구조는 그대로 — 소스만 늘어난다

주의: 원시 가속도계 피크 검출(위상 동기화)은 트랙 B에서도 하지 않는다.
CMPedometer의 분당 케이던스면 리듬 레이어까지 충분하다. 위상까지 가는 것은
그 다음 검증(리듬 레이어가 실제로 사랑받는가) 이후의 문제다.
